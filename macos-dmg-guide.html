准备工作
开始之前需要了解的基础知识
💡
什么是 DMG 打包？
DMG（Disk Image）是 macOS 上的磁盘映像格式，用户双击即可挂载并拖拽安装应用。对于 Electron 应用，我们需要先构建应用，然后打包成 DMG 格式供用户下载。
注册 Apple Developer 账号
访问 Apple Developer Portal 注册开发者账号。 必需 年费 $99，用于代码签名和公证。
了解签名与公证的区别
代码签名（Code Signing）：验证应用来源，防止篡改。
公证（Notarization）：Apple 云端扫描，确认应用无恶意软件。
Staple：将公证结果附加到应用中，离线也能验证。
确认项目使用 electron-builder
本项目使用 tools-pack 工具调用 electron-builder 进行打包。确保 package.json 中已配置好 build 字段。

获取 Apple 证书
创建并导出 Developer ID 证书
⚠️
注意： 不要使用普通的 Development 证书，必须使用 Developer ID Application 证书才能对外分发应用。
在 Apple Developer Portal 创建证书
1. 登录 developer.apple.com
2. 进入 Certificates, Identifiers & Profiles → Certificates
3. 点击 + 创建新证书
4. 选择 Developer ID Application（用于分发）
5. 上传 CSR（Certificate Signing Request）文件
生成 CSR 文件（如需要）
在 Mac 上打开 Keychain Access，选择菜单 Certificate Assistant → Request a Certificate From a Certificate Authority，填写信息保存为 .certSigningRequest 文件。
下载并导出 .p12 证书
1. 下载生成的 .cer 文件并双击安装到 Keychain
2. 在 Keychain Access 中找到该证书（通常在 "My Certificates"）
3. 右键证书 → Export → 选择 .p12 格式
4. 设置一个强密码（后续需要用到）
生成 Base64 编码
在终端执行以下命令，将 .p12 转为 Base64 字符串：
bash 
# 将 .p12 证书转为 base64（macOS/Linux）
base64 -i your-certificate.p12 -o cert-base64.txt

# 或使用 openssl
openssl base64 -in your-certificate.p12 -out cert-base64.txt

# 查看生成的内容（很长的字符串）
cat cert-base64.txt
✅
保存好以下信息：
• cert-base64.txt 中的内容 → 用于 APPLE_SIGNING_CERTIFICATE_BASE64
• 导出 .p12 时设置的密码 → 用于 APPLE_SIGNING_CERTIFICATE_PASSWORD

配置 GitHub Secrets
在仓库设置中添加敏感信息
📍
路径：仓库 Settings → Secrets and variables → Actions → New repository secret
Secret 名称 类型 获取位置 用途
APPLE_SIGNING_CERTIFICATE_BASE64 必需 上一步生成的 Base64 字符串 代码签名证书
APPLE_SIGNING_CERTIFICATE_PASSWORD 必需 导出 .p12 时设置的密码 证书密码
APPLE_ID 必需 Apple ID 邮箱 Notarization 账号
APPLE_APP_SPECIFIC_PASSWORD 必需 Apple ID → App-Specific Passwords 应用专用密码
APPLE_TEAM_ID 必需 Apple Developer → Membership → Team ID 开发者团队 ID
🔍 如何获取 Apple 应用专用密码 ▼
  1. 访问 appleid.apple.com
  2. 登录你的 Apple ID
  3. 进入 Sign-In and Security
  4. 点击 App-Specific Passwords
  5. 点击 Generate an app-specific password
  6. 输入名称（如 "GitHub Actions"），点击 Create
  7. 复制生成的密码（格式如：abcd-efgh-ijkl-mnop）
⚠️
应用专用密码只会显示一次，请务必保存好！
🔍 如何获取 Team ID ▼
  1. 登录 Apple Developer Portal
  2. 点击右上角 Account
  3. 进入 Membership Details
  4. 找到 Team ID（格式如：ABC123DEF4）

GitHub Actions 工作流配置
配置 YAML 文件实现自动化打包
📁
工作流文件位置：.github/workflows/release-stable.yml

🎯 核心配置解析

yaml 
# 1. 准备 Apple 签名证书
- name: Prepare Apple signing certificate
  env:
    APPLE_SIGNING_CERTIFICATE_BASE64: ${{ secrets.APPLE_SIGNING_CERTIFICATE_BASE64 }}
    APPLE_SIGNING_CERTIFICATE_PASSWORD: ${{ secrets.APPLE_SIGNING_CERTIFICATE_PASSWORD }}
  run: |
    cert_path="$RUNNER_TEMP/open-design-signing.p12"
    # 解码 base64 证书到临时文件
    printf '%s' "$APPLE_SIGNING_CERTIFICATE_BASE64" | base64 --decode > "$cert_path"
    # 设置 electron-builder 环境变量
    {
      echo "CSC_LINK=$cert_path"
      echo "CSC_KEY_PASSWORD=$APPLE_SIGNING_CERTIFICATE_PASSWORD"
    } >> "$GITHUB_ENV"
yaml 
# 2. 构建 macOS 应用（带签名和公证）
- name: Build release mac artifacts
  env:
    # Notarization 凭据
    APPLE_ID: ${{ secrets.APPLE_ID }}
    APPLE_APP_SPECIFIC_PASSWORD: ${{ secrets.APPLE_APP_SPECIFIC_PASSWORD }}
    APPLE_TEAM_ID: ${{ secrets.APPLE_TEAM_ID }}
  run: |
    # 调用 tools-pack 构建 macOS 应用
    pnpm exec tools-pack mac build \\
      --dir "$RUNNER_TEMP/tools-pack" \\
      --namespace release-stable \\
      --portable \\
      --app-version "${{ inputs.release_version }}" \\
      --mac-compression normal \\
      --to all \\
      --json \\
      --signed       # 启用代码签名
      --notarize     # 启用公证

📋 关键参数说明

参数 说明
--signed 启用代码签名，使用 CSC_LINK 和 CSC_KEY_PASSWORD 环境变量
--notarize 启用 Apple Notarization，需要 APPLE_ID、APPLE_APP_SPECIFIC_PASSWORD、APPLE_TEAM_ID
--to all 构建所有目标格式（DMG + ZIP）
--mac-compression normal 使用标准压缩率
💡
electron-builder 自动读取的环境变量：
• CSC_LINK：指向 .p12 证书文件的路径
• CSC_KEY_PASSWORD：证书密码
• APPLE_ID / APPLE_APP_SPECIFIC_PASSWORD / APPLE_TEAM_ID：Notarization 凭据

验证与发布
确认签名和公证成功

🔍 验证签名和公证

bash 
# 1. 挂载 DMG 文件
hdiutil attach "Open Design.dmg" -nobrowse -readonly -mountpoint /tmp/mnt

# 2. 验证代码签名
codesign --verify --deep --strict "/tmp/mnt/Open Design.app"

# 3. 验证公证（Staple）
xcrun stapler validate "/tmp/mnt/Open Design.app"

# 4. 评估 Gatekeeper 信任
spctl --assess --type execute --verbose=4 "/tmp/mnt/Open Design.app"

# 5. 卸载 DMG
hdiutil detach /tmp/mnt

📤 发布到 GitHub Release

yaml 
# 准备发布资源
- name: Prepare release assets
  run: |
    VERSION="${{ inputs.release_version }}"
    ASSETS_DIR="$RUNNER_TEMP/release-assets"
    mkdir -p "$ASSETS_DIR"

    # 复制 DMG 和 ZIP 文件
    cp "$SDIR/dmg/Open Design-release-stable.dmg" \\
      "$ASSETS_DIR/Open Design-$VERSION-mac-arm64.dmg"
    cp "$SDIR/zip/Open Design-release-stable.zip" \\
      "$ASSETS_DIR/Open Design-$VERSION-mac-arm64.zip"

    # 生成 SHA256 校验和
    cd "$ASSETS_DIR"
    shasum -a 256 "Open Design-$VERSION-mac-arm64.dmg" > "Open Design-$VERSION-mac-arm64.dmg.sha256"

常见问题排查
遇到问题时的解决方案
❌ "The provided certificate is not valid for code signing"
确保证书类型是 Developer ID Application，而不是 Development 或 Distribution 证书。
❌ "Notarization failed: Invalid or missing credentials"
检查 APPLE_ID、APPLE_APP_SPECIFIC_PASSWORD、APPLE_TEAM_ID 是否正确。注意应用专用密码不是 Apple ID 的登录密码。
❌ "The binary you uploaded was not valid"
可能是证书过期或权限问题。检查证书有效期，并确保 Apple Developer 账号处于活跃状态（年费已缴纳）。
❌ "Stapler validate" 失败
公证过程可能需要几分钟到几小时。如果刚完成公证就验证，可能还来不及同步。等待一段时间后重试。
